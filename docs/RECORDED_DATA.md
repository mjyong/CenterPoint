**T36 体检的结果**（2026-11-05）：

- 四份都是 100% RTK 固定解（`pos_type` 56），时钟正常，四路相机齐；
- **狗全程几乎没动**：四份合计走了约 7 m，所有场景都是 `static`。每份 bag 是一个机位，看路过的车；
- 天线接法从这批数据判断不了。按接正（偏置 0、杠杆臂 IMU 中心）转换，meta 里 `ins_azimuth_offset_from` 是 `given`，**未验证**。狗不动时偏置不影响检测系里的点和框（实测差 3 mm）；
- 场景：cp01 3 个、cp02 5 个、cp03 16 个、cp04 7 个（keep），每个约 30 s。

- 离地高度（每 10 帧估一次的中位数）：cp01、cp02 约 0.48 m，cp03、cp04 约 0.63 m（人说趴着和站着都有）；
- 地点：和 0921 同一个厂区，相距几百米。T34 在狗上看到的北纬 40°、东经 116° 是 `ins_status` 1（没有解）时的值，不是位置。

**怎么用**（2026-11-05 人定）：1104 按整份 bag 分，两份做验证、两份做训练（默认验证 cp02 + cp04，训练 cp01 + cp03；各有一份趴着、一份站着），0921 的划分不变。见 SERVER_TASKS.md 的 T37。

## 4. 以后怎么追加

每来一批新 bag：

1. 放到 `/public/zjst/robot/<名字>/`，在本仓库根建同名软链（需要时在 `d20car_predict/` 下也建一份）；
2. 在本文「总览」加一行，并新开一节写日期、路径、各 bag 时长 / 体积 / 话题 / 已知问题；
3. 现场元信息（区域、天气、可控场景记录表）一并写进该节。

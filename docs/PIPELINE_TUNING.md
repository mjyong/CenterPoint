# 后处理、跟踪、预测的调试计划（2026-10-26）

**目标**：在 0921 的验证场景上，逐段调好检测之后的三段，每一步都有指标、有可视化：
- 后处理：过滤、上报阈值；
- 跟踪：关联、确认、运动状态；
- 轨迹预测。

最后用定下来的参数完整跑一遍流水线，看最终效果。

**主要看什么**由用途决定：狗要及时发现运动的车并停下（[DATA_COLLECTION_PLAN.md](DATA_COLLECTION_PLAN.md) 开头）。所以主要看 30 m 内的车：
- 运动的车有没有及时报出来；
- 停着的车会不会被当成在动，让狗白停；
- 预测的路径准不准。

检测模型本身在 T15 里定（上线用哪个 Pillar），这里不再动网络。服务器上的步骤见 [SERVER_TASKS.md](SERVER_TASKS.md) T18–T22。原理见 [DETECTION_POSTPROCESS.md](DETECTION_POSTPROCESS.md)、[TRACKING_PREDICTION.md](TRACKING_PREDICTION.md)。

## 1. 数据

| | 验证 10 个场景 | 训练 25 个场景 |
|---|---|---|
| 标签 | `labels_sustech2.pkl`：只有关键帧（2 Hz，580 帧），人审过 | `labels_train2.pkl`：每帧（10 Hz，7,232 帧），关键帧审过，中间是插值 |
| 车辆轨迹（不含忽略） | 94 条，其中运动的 28 条 | 244 条，其中运动的 41 条 |
| 预测样本（运动、关键帧、后面还有 3 s 标注） | 174 个（30 m 内 127 个） | 245 个（30 m 内 161 个） |
| 运动时离狗最近不到 10 m 的车 | 5 辆（不到 5 m 的 3 辆） | 3 辆（不到 5 m 的 1 辆） |
| 上线的 Pillar 训练时见过 | 没见过 | 见过 |

两份数据怎么用：
- **A（主）**：验证 10 个场景，用上线 Pillar 的检测。
- **B（防过拟合）**：训练 25 个场景，用 nuScenes Pillar 的检测（它没见过这些场景），只在关键帧上评。
  - 上线 Pillar 在训练场景上检得太好，拿它调出来的跟踪参数会太信任检测，所以 B 不用它。
  - B 的作用是检查：在 A 上调好的参数，换一个更差、误差不同的检测器还成不成立。
- **预测的 oracle 评估**：把标签当成检测喂给跟踪器，只看预测器本身的误差。IMM 不用训练，所以 35 个场景都能用，需要 10 Hz 的标签：
  - 训练场景用 `labels_train2.pkl`；
  - 验证场景在 T18 里按 T17 第 2 步传播出 `labels_full2.pkl`。这个文件只用来画图和 oracle，不用来算检测 AP。

## 2. 指标

都只评车辆，40 m 内。和忽略框配上的检测、轨迹不算误报；忽略框不算漏报。

GT 框当前帧一个点都没有的（被挡住、在盲区里）：
- 不算漏报；
- 跟踪器在那里 coast 出来的轨迹，也不算误报。

| 段 | 指标 | 主要看 | 说明 |
|---|---|---|---|
| 后处理（上报的检测） | precision、recall（2 m 内配上算对），分 0–30 m 和 30–40 m；每分钟误报数 | **30 m 内 recall**，误报不多于基线 | 关键帧上算 |
| 跟踪 | MOTA、**IDF1**、每分钟 ID 切换、FRAG、MT / ML；每分钟假轨迹；确认延迟（车第一次出现在 30 m 内，到第一次被一条确认的轨迹配上，p50 / p90） | **IDF1**、假轨迹 / 分钟、确认延迟 p90 | 跟踪器照常 10 Hz 跑，只在关键帧上和 GT 比，和 nuScenes 一样。误报、漏报按原因分开数，沿用 `nusc_clip_eval.py` 的分法 |
| 运动状态 | 相关运动段（≥ 1 m/s、30 m 内）的漏报和报出延迟 p90；停着的车被报成运动的次数 / 小时 | **相关漏报**、**误报 / 小时** | 就是 `motion_eval.py` 的表，并进同一份报告 |
| 预测 | 运动车辆的 ADE、FDE（最可能的那个模式）、minADE / minFDE、MR@2m，分 1 / 2 / 3 s；分直行和转弯（3 s 内航向变化 > 15°）、分车速（1–3、3–6、> 6 m/s） | **3 s FDE**、MR@2m | 比较 IMM（现在的 tier 1）和匀速（CV）。分 oracle 和端到端两种 |
| 预警（端到端） | 应报：车在 3 s 内会进到狗周围 R m 以内（按标注的未来位置和狗的实际位置算）。报出：一条运动状态的轨迹，最可能的预测路径进到 R m 以内。指标是应报里报出了多少、报出时离最近点还有几秒、每小时误报几次 | 先只出数，不拿来定参数 | R 默认 5 m，等规划那边的停车规则定了再改。0921 上样本太少（第 5 节） |
| 耗时 | 后半段（过滤 + 跟踪 + 预测）每帧 ms | 不超过现在的 2 倍 | 服务器 CPU 上测，Orin 上的等 H2 |

**区间**：样本少，每个数都按场景重抽（bootstrap）给 90% 区间。两个配置比的时候，给"A 领先的比例"，和 T7 一样。

## 3. 可视化

**每个验证场景一个 Foxglove MCAP**。话题如下，3D 面板里每个都能单独开关：

| 话题 | 画什么 |
|---|---|
| `/lidar` | 当前帧点云（世界系） |
| `/gt/boxes` | 关键帧的标注：绿 = 跟上了，红 = 漏了，灰 = 忽略或没点。非关键帧画 10 Hz 的插值标签（细线） |
| `/gt/paths` | 标注的过去 2 s（实线）、未来 3 s（虚线） |
| `/det/boxes`、`/det/low_score` | 上报的检测（误报描红）、只给跟踪用的低分检测 |
| `/det/filtered` | 被后处理过滤掉的检测，标上原因：点太少、飘在空中、沉到地下、跨类重复 |
| `/track/boxes`、`/track/history` | 轨迹（颜色按 ID，文字是 ID、分数、速度、运动状态）和走过的路 |
| `/pred/paths` | 预测的几个模式（线宽、透明度表示概率），3 s 处的 1σ 椭圆，和到标注终点的 FDE 线段 |
| `/events`、`/log` | ID 切换、漏检、假轨迹、运动误判（Log 面板里可以点着跳过去） |
| `/ego`、`/blind` | 狗的位置和轨迹；盲区扇形（142°–218°），两侧各 20° 的边带 |
| `/metrics/frame` | 每个关键帧的数，Plot 面板用：累计 MOTA、假轨迹数、FDE 等 |

0921 没有相机，只有点云。仓库里附一个 Foxglove 布局文件：3D、Plot、Log 三个面板。

**报告** `report.md` / `report.json` 包括：
- 第 2 节各项指标的表、区间；
- 误报、漏报的原因分解；
- 每个场景中间那个关键帧的鸟瞰图（PNG）。

**问题清单** `issues.csv`：每类问题按严重程度列前 N 条。
- 类型：ID 切换、漏掉的运动车、持续 ≥ 1 s 的假轨迹、停着的车被报成运动、FDE 最大的预测。
- 每条带场景、场景里的秒数、轨迹 / 标注 ID、距离，以及方位区（盲区 / 边上 / 其他）。
- 在 Foxglove 里拖到那个时间看。

**扫参**：
- `sweep.csv`，每组参数一行，主要指标加区间；
- 结果出来以后，我做一个网页看板，把各组参数并排比。

| 扫参 | 无 | 离线重跑后半段（CPU，不用 GPU），`--set` 给参数网格，每组一行 |

新工具是 `tools/dog/pipeline_eval.py`。
- **输入**，每个场景：`results.pkl`（某个检测模型重放验证场景的结果）、存好的输入帧、标签。
- **做的事**：离线重跑过滤 → 跟踪 → 预测，算第 2 节的指标，写第 3 节的 MCAP、报告、问题清单。
- **快**：后半段是 CPU，10 个场景一组参数大约 1 分钟，可以并行。
- **为什么要拼 GT 的 ID**：验证标签里大约 19 处，同一辆车前后两段是两个 ID（停着的车中间丢过，或者一段接一段）。不拼起来，IDF1 和 ID 切换会冤枉跟踪器。拼了多少，写进报告。

## 6. 局限

- **验证集小**：
  - 28 条运动的车、174 个预测样本，区间会宽，小的改进分不出来。
  - "车靠近狗时报得及不及时"在 0921 上几乎没有样本：运动时离狗不到 10 m 的车，验证、训练合计只有 8 辆。
  - 工具先把预警指标做好，等 [DATA_COLLECTION_PLAN.md](DATA_COLLECTION_PLAN.md) 3.2 的可控场景（迎面驶来、横穿、驶来后停下）采到了，直接评。
- **最终数字偏乐观**：调参和最后报数用的是同一个验证集。独立的测试集见 DATA_COLLECTION_PLAN 3.5。
- **验证标签只有关键帧**：跟踪指标只在 2 Hz 上算，一次很短的 ID 切换、或者两个关键帧之间的短暂丢失，可能看不到。
- **验证标签偏向两个 nuScenes 教师**（T17 复核）：只影响检测的比较，对调跟踪、预测影响不大。
- **学出来的预测器（tier 2）先不训**：狗数据上运动的车一共 69 条，不够。先只调 IMM，等可控场景和自然交通的数据攒够了再说。
